# 0.4.8: client recovery, public rooms and power levels, durable local tier, light server

No secrets, invite codes, domains or addresses appear here.

## Daemon recovery (`m4a-web-client`)

What used to stick after "homeserver http failed", and what changed:

- The push socket had no watcher: once it died (server restart, network loss) it was never opened again, so new rooms and events stopped arriving. `PushLink::is_alive` now reports a finished worker; `MachineClient::tick` opens a new socket at most every 5 seconds (and the engine's `Live::wait_for_news` does the same).
- The same happens when sessions fail to drive for 5 ticks in a row: the push socket is rebuilt as well.
- The HTTP pool no longer keeps idle connections for long (15 s idle timeout, TCP keepalive 30 s), so a connection that outlived a server restart is not reused.
- The loop backs off (250 ms doubling up to 10 s) while a tick fails and returns to 250 ms after the first clean tick. It prints one line when failing starts and one at the tenth failed tick, nothing else new.
- Nothing is lost on a swap: events the old socket still held are handed to their sessions first.

Not covered: a hard hang inside one blocking call (the request timeout of 60 s and the 45 s sync wait still bound it) and a daemon whose process died; a supervisor is still needed for that.

## Ordinary public room and power levels (`m4a`)

- `m4a --as NICK create <name> --public`: creates the server's public room shape, then lowers the write level (`events_default`) to 0 so everyone who joins can write. `--channel` stays the broadcast shape (creator and level-50 users write). `create` without flags is still the private group.
- `m4a --as NICK power <room> [--default N] [<user> <level>]`: changes the room's `m.room.power_levels` (copy of the current content, with `events_default` and/or one user's level replaced). `<user>` is a nick or a full id. A user set to the room's `users_default` is dropped from the list. The server decides whether the caller is allowed; a refusal is reported as the failed command.
- Socket commands: `rooms.create` accepts `kind: public`; `rooms.power` takes `room`, optional `events_default`, optional `user` with `level`.
- Core: `MessengerCommand::SetPowerLevels`.

Encryption of a public room is whatever the server gives its public shape; this release does not add an unencrypted room kind to the server.

## Durable local tier

The in-process bus keeps its rooms and messages in memory by default (lost on restart). Set `M4A_LOCAL_BUS_DB` to a file path to keep them: the file, its `.key` neighbour and the directory are created owner-only (0600/0700), WAL on. The key pragma protects the file only when SQLite is built as SQLCipher; otherwise the file mode is the protection, so put it under the owner's private store root. Sessions are re-seeded on start (`INSERT OR REPLACE`), so a restart reuses the stored rows. Off by default.

## Light server

`mail4agent-server` is now a workspace dependency with `default-features = false`; crates that need the full server (`mail4agent-messenger-shell` local bus, `m4a-edge`, `m4a-product-example`, server-bin tests) name its features themselves, so behaviour of full builds is unchanged. The server binary built with `--no-default-features` no longer links `m4a-matrix-core` or `image`: no hash-id rooms, presence, remote media or thumbnails. The code stays; only features switch it off.

`scripts/check-light-server.sh` builds and tests it and fails if either crate is linked. In a light build the three federation reads `state_ids`, `state` and `event_auth` are not served (federation is off by default anyway); the spec probe knows this. A database written by a full build should not be opened by a light build (see f3-default-and-migration.md).
